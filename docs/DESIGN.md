# Mer Harness（メルハーネス）デザイン方針書

> 2026-10-02 確定: 表示名 "Mer Harness"、ロゴは「Harness」のみ。データは D1 が正（§10.5 の IndexedDB 案は不採用、PWA は静的シェルのみキャッシュ）。

> 非公式の個人用ツール。メルカリの赤・ロゴ・書体の印象は使わない。独自ブランド「Harness」として成立させる。

---

## 1. ブランドコンセプト

### 1.1 一言コピー
- **メイン**: 「面倒を、ひと引きの推進力に。」
- **サブ**: 「撮って、答えて、ピコーン。」
- **英題**: *Harness the hassle.*

### 1.2 ハーネスの比喩
ハーネス（harness）は馬具で、力を無駄なく前へ伝える装具。クライミングの安全帯、プログラミングの test harness（作業を支える足場）にも通じる。このアプリは出品の面倒を消すのではなく、力が前に進む形へ整える。

| 比喩 | UIでの現れ |
|---|---|
| 手綱（reins） | 進捗バーを「引き革」に見立てる。細い2本線が張る表現 |
| 留め具（buckle） | 完了時の「カチッ」。バックル音を小SEに採用 |
| 装備（gear） | 実績バッジを「装備品」と呼ぶ。ストラップ、バックル、ベルなど |
| 馬（駆ける力） | 過度に擬人化しない。蹄のモチーフは最小限（ロゴの一点のみ） |
| 荷（cargo） | 在庫は「積荷」。発送チェックは「積み込み」 |

馬のイラストは使わない。モチーフは **ストラップ・バックル・ステッチ（縫い目）** に限る。UIの罫線を「縫い目（破線 `2 3`）」にすると、装備感を安く出せる。

### 1.3 トーン&マナー
- **キーワード**: 頼れる / 軽快 / 手触りがある / ちょっと誇らしい
- **人格**: 優秀な相棒。急かさず、褒めすぎず、成功の瞬間だけ全力で祝う。
- **言葉**: 「です・ます」はやめ、軽い口語（「撮ろう」「いい感じ！」）。絵文字は成功系のみ最小限で使う。
- **NG**: 煽り（「早く売らないと損」）、罪悪感（「ストリークが切れちゃう…」）、メルカリ公式を思わせる言い回し。

### 1.4 ロゴ方向性
- **ワードマーク**: 「Harness」を M PLUS Rounded 1c ExtraBold（800）で組む。`H` の横棒をストラップに見立て、右端にバックルの小さな四角（□）を置く。
- **シンボル**: 角丸正方形（半径 28%）の中に、斜めに掛かるストラップと中央のバックル穴1つ。2色（primary + XPゴールド）で収める。
- **ロックアップ**: 日本語表記「ハーネス」はサブとして小さく添える。「Mercari」の語は文脈上の説明（例:「メルカリ用」）に留め、ロゴには入れない。
- **アプリアイコン**: primary 地にゴールドのバックル。背景はフラットで、グラデーションなし。maskable 対応で中心 60% に収める。

## 2. カラーパレット

方針: 赤を避ける。**インディゴ（信頼・夜明け前）を主役**、**ゴールドを「報酬専用色」**として分離する。ゴールドを他の用途に使わないことが、報酬の特別感を保つ。

### 2.1 ライト

| 役割 | トークン | HEX | 用途 |
|---|---|---|---|
| base | `--c-base` | `#F6F5F1` | アプリ背景（温かい紙色） |
| surface | `--c-surface` | `#FFFFFF` | カード |
| surface-2 | `--c-surface-2` | `#EEEDE7` | 入れ子、入力欄背景 |
| line | `--c-line` | `#DAD8CF` | 縫い目罫線 |
| text | `--c-text` | `#1B1D2A` | 本文（base比 約15:1） |
| text-sub | `--c-text-sub` | `#555869` | 補助（base比 約6.5:1） |
| primary | `--c-primary` | `#3B4BD8` | 主要ボタン、リンク（白文字比 約6.6:1） |
| primary-press | `--c-primary-press` | `#2D3AB0` | 押下 |
| primary-soft | `--c-primary-soft` | `#E4E7FB` | 選択状態の背景 |
| accent | `--c-accent` | `#00B8A9` | 撮影枠、ガイド、AI/自動化の示唆 |
| accent-ink | `--c-accent-ink` | `#006B63` | accent色のテキスト用 |
| success | `--c-success` | `#1F9D6B` | 完了、売れた |

| danger | `--c-danger` | `#C2394B` | 削除など破壊的操作のみ（赤系だがロゴには使わない） |

### 2.2 ダーク
純黒は使わず、青みを帯びた墨色にする。有彩色は明度を上げ、彩度を少し落とす。

| 役割 | HEX |
|---|---|

| surface | `#191C28` |
| surface-2 | `#232736` |
| line | `#323750` |
| text | `#ECEDF4`（約15:1） |
| text-sub | `#A3A7BD`（約7:1） |
| primary | `#8E9BFF`（暗色文字 `#10121B` を載せる。約7:1） |
| primary-soft | `#262C5C` |

| xp-gold | `#FFC933` |
| warning | `#FFA040` |
| danger | `#FF7A8A` |

### 2.3 コントラスト・使用ルール
- テキストは WCAG AA（通常 4.5:1、大文字・UI部品 3:1）以上。ゴールドと accent は **地色に使い、文字にするときは `-ink` を使う**。
- 状態を色だけで伝えない。必ずアイコンまたはラベルを併用する（例: ✓ 完了、! 注意）。
- ゴールドは **XP、レベル、売上金** の3つ専用。ボタンやリンクには使わない。
- グラデーションは、祝福演出の背景（primary→accent の 135°）と XP バーの光沢のみ。
- 紙吹雪の色: `#F5B301 / #3B4BD8 / #00B8A9 / #FF8FB1 / #FFFFFF`（ピンクは演出専用の差し色で、UIには出さない）。

## 3. タイポグラフィ

### 3.1 選定
| 用途 | フォント | 理由 |
|---|---|---|
| 見出し・数字強調・ロゴ | **M PLUS Rounded 1c**（700/800） | 丸ゴシックで親しみがある。ゲーム感が出る。メルカリの角ゴ系の印象と離せる |
| 本文・入力・出品文プレビュー | **Noto Sans JP**（400/500/700） | 可読性が高く、出品文の確認で誤読しにくい。ウェイトが豊富 |
| 数字（金額・XP・タイマー） | **Inter**（600/700, `tnum`） | 数字の字形が整い、等幅数字で桁揃えできる。金額が主役の画面向き |

- すべて Google Fonts（OFL）。OSS 配布時もライセンスが問題にならない。
- 配信は **self-host + `font-display: swap` + サブセット化**（日本語は `unicode-range` 分割済みの woff2）。初回表示は system-ui フォールバックで描画する。
- スタック例:
  - `--font-display: "M PLUS Rounded 1c", "Hiragino Maru Gothic ProN", system-ui, sans-serif;`
  - `--font-body: "Noto Sans JP", "Hiragino Sans", "Yu Gothic", system-ui, sans-serif;`
  - `--font-num: "Inter", "M PLUS Rounded 1c", ui-monospace, sans-serif;`
- 数字には `font-variant-numeric: tabular-nums` を指定する。

### 3.2 サイズスケール（ベース 16px、スマホ）
| トークン | size / line-height | weight | 用途 |
|---|---|---|---|
| `--fs-display` | 40 / 44 | 800 Rounded | 祝福演出の大文字、「ピコーン！」 |
| `--fs-h1` | 28 / 34 | 800 Rounded | 画面タイトル、売上金額 |
| `--fs-h2` | 22 / 28 | 700 Rounded | セクション見出し、質問文 |
| `--fs-h3` | 18 / 26 | 700 | カードタイトル |
| `--fs-body` | 16 / 26 | 400 | 本文 |
| `--fs-body-s` | 14 / 22 | 400 | 補助 |
| `--fs-caption` | 12 / 16 | 500 | ラベル、タブ |
| `--fs-num-xl` | 48 / 52 | 700 Inter | ダッシュボードの金額 |

- 日本語本文の `letter-spacing` は `0.02em`。見出しは `0`。
- 1行の文字数は全角 22〜30 文字を目安にする。
- 最小タップ領域は **48×48px**（主要ボタンは高さ 56px）。

## 4. 画面レイアウト

共通ルール:
- 幅 360〜430px を基準にし、左右余白 16px、カード間隔 12px、カード角丸 20px。
- 下部タブバー（高さ 64px + safe-area）: ホーム / 積荷 / ＋（撮影）/ 実績。**中央の＋はバックル形のFAB**（56px、primary）。
- 親指が届く下半分に主要操作を置く。
- 区切り線は縫い目（`1.5px dashed var(--c-line)`）。

```
├──────────────────────────┤
│ 売上金                    │

├──────────────────────────┤
│ きょうのひと引き          │

│ │ ▶ Pixel 10 Pro Fold │   │ ← 次の一手カード（1枚だけ）
```

- 売上金は **¥ とカンマを含めた1つの数値** で、カウントアップ演出に対応する。

### 4.2 撮影 & トリミング
```
┌──────────────────────────┐
│ ✕           1/6 枚  ⚡     │
│ ┌────────────────────┐   │
│ │ ┌ ─ ─ ─ ─ ─ ─ ┐    │   │
│ │ │   正方形ガイド │   │   │ ← 縫い目枠（accent）
│ │ └ ─ ─ ─ ─ ─ ─ ┘    │   │
│ │  「白い紙の上に置こう」│  │
│ └────────────────────┘   │
│ ○ ○ ○ ○ ○ ○  ← 撮影済み  │
│        (◉ 撮影)          │
└──────────────────────────┘
        ↓ 撮影後
┌──────────────────────────┐
│ [ 元 | 自動 ] ← 比較スライダ │
│ ┌────────────────────┐   │
│ │  1:1 トリミング済み │   │
│ └────────────────────┘   │
│ ◀ 位置と拡大を微調整 ▶   │
│ [やり直す]   [これでOK ✓]│

```
- 自動トリミング: 被写体を検出し、**正方形・中央・余白 8%**。背景は白〜生成りに補正し、明るさを +10% 程度補正する。
- 補正前後を **スワイプ比較**で見せ、自動処理の結果が納得できるようにする。
- 1枚目が正方形トリミング済みになった時点で「サムネ完成」を軽く祝う（小演出）。

### 4.3 質問カード（出品文が育つ）
画面を上下に2分割する。**上: 出品文プレビュー（育つ文章）／下: 質問カード**。

```
┌──────────────────────────┐
│ 出品文  ▓▓▓▓░░ 4/6      │
│ ┌────────────────────┐   │
│ │ 【Google】Pixel 10 │   │
│ │ Pro Fold 512GB     │   │ ← 確定済み部分は濃色
│ │ 状態：目立った傷や… │   │
│ │ サイズ：▒▒▒▒▒     │   │ ← 未回答は薄いプレースホルダ
│ └────────────────────┘   │
├──────────────────────────┤
│ Q4  傷や汚れはある？      │
│ ┌──────┐ ┌──────┐       │
│ │ なし  │ │ 小さい │       │
│ └──────┘ └──────┘       │
│ ┌──────┐ ┌──────┐       │
│ │ 目立つ │ │ 写真で │       │
│ └──────┘ └──────┘       │
│ ← 戻る       スキップ →  │
└──────────────────────────┘
```
- 質問は **1画面1問、選択式を優先**、自由入力は最後に任意で置く。
- 順序は ブランド → 状態 → サイズ → 付属品 → 傷。答えるたびに、プレビューの該当行が **薄いプレースホルダから確定文へ育つ**。
- 育つ見せ方:
  1. 回答タップ → 選択肢が primary-soft に反転（80ms）。
  2. 該当行の文字が **左から右へ「タイプ」されるのではなく、フェードイン + 下から4px**で確定（240ms）。
  3. 行頭に小さな ✓（success）がぽんと出る。
  4. 進捗の引き革（細線）が1段張る。
- スキップした項目は黄色の点線で「あとで」と表示し、完成度を責めない。
- 出品文が 100% 揃うと、次の画面へ進むバックルボタンが現れる。

### 4.4 価格提案
```
┌──────────────────────────┐
│ 価格を決めよう            │
│ 相場メモ                  │
│  ¥178,000 ┤ ●━━━━━○    │
│  ¥195,000 ┤       ▲ 提案│
│  ¥215,000 ┤             │
│ ┌────────────────────┐   │
│ │ すぐ売る  ¥182,000  │   │
│ │ ★おすすめ ¥195,000  │   │ ← 初期選択
│ │ 強気      ¥208,000  │   │
│ └────────────────────┘   │
│ 手数料10% → 手取り ¥175,500│
│ [ 価格を決定 ]            │
└──────────────────────────┘
```
- 3段階（すぐ売る / おすすめ / 強気）。**おすすめ = 相場メモ中央値の 0〜+3%**、すぐ売る = −6%、強気 = +7%（目安）。
- 手取りは常時表示する。手数料率は設定で変更できる（初期値 10%）。
- 相場メモは手入力の範囲（最小〜最大）。HoloLens 2（3.5〜4.8万）のようにレンジが広い品は、レンジ全体を帯で見せ、提案位置をマーカーで示す。

## 5. モーション仕様

### 5.1 基本トークン
| トークン | 値 |
|---|---|
| `--dur-instant` | 80ms |
| `--dur-fast` | 160ms |
| `--dur-base` | 240ms |
| `--dur-slow` | 400ms |
| `--dur-celebrate` | 1200〜2400ms |
| `--ease-out` | `cubic-bezier(0.2, 0.8, 0.2, 1)` |
| `--ease-in-out` | `cubic-bezier(0.65, 0, 0.35, 1)` |
| `--ease-spring` | `cubic-bezier(0.34, 1.56, 0.64, 1)`（軽いオーバーシュート） |

画面遷移は 240ms の横スライド（ease-out）を基本とする。

### 5.2 イベント別

| イベント | 規模 | 段階（タイムライン） | 紙吹雪 |
|---|---|---|---|
| **質問に回答** | S | 0ms 選択反転 → 80ms 行がフェードイン+4px（240ms）→ 200ms ✓ がスプリングで出る（scale 0→1.15→1, 280ms）→ `+5XP` が 24px 浮上して 600ms でフェード | なし |
| **出品完了（登録）** | L | 0ms 画面暗転 20% → 100ms「ピコーン！」が scale 0.6→1.1→1（スプリング 420ms）→ 200ms 紙吹雪 → 500ms XP が浮上して XP バーが充填（600ms）→ 1800ms にバナー自動退場 | 60粒 / 1.4s |
| **売れた** | XL | 0ms フラッシュ（白 12%・80ms）→ 売上金額が 0→金額へカウントアップ（900ms, ease-out）→ 紙吹雪 → ゴールドのコインが 8枚 放物線で売上金カウンターへ吸い込まれる（各 600ms, 80ms ずつ時差）→ XP 加算 | 120粒 / 2.0s（2回の連射） |
| **発送完了** | L | チェックリスト全項目が上から 40ms ずつ連鎖して光る → バックルが「カチッ」と閉まる（rotate 8°→0, 160ms）→「ピコーン！」→ 紙吹雪 | 80粒 / 1.6s |
| **レベルアップ** | XL | XP バーが満タンで一瞬発光 → リングが 1.0→1.25→1.0（500ms）→ 新レベル数字がカードフリップ（400ms）→ 全画面の放射線ライト（accent→gold, 700ms）→ 報酬カード表示（タップで閉じる） | 150粒 / 2.4s |
| **ストリーク更新** | M | 🔥 が scale 1→1.3→1（360ms）+ 数字がローリング（縦に 1 桁送り, 240ms）。節目（7/30/100日）のみ紙吹雪 | 通常なし／節目 50粒 |
| **コンボ** | M | 画面上部に「x1.5 COMBO」のチップが右からスライドイン（200ms）。残り時間を細いバーが縮む（20分→0）。2連目以降、チップが毎回小さくバウンド | なし（4連目のみ 30粒） |

### 5.3 紙吹雪の段階
| 段階 | 粒数 | 持続 | 使用 |
|---|---|---|---|
| none | 0 | – | 回答、チェック |
| small | 30 | 1.0s | コンボ4連、ストリーク節目 |
| medium | 60 | 1.4s | 出品完了 |
| large | 80〜120 | 1.6〜2.0s | 発送完了、売れた |
| burst | 150 | 2.4s | レベルアップ、実績初回 |

- 粒の形は **長方形（6×10px）と円（6px）の2種**。重力 0.35、横風 ±0.1、回転はランダム。
- 描画は **Canvas 1枚**（`position: fixed; pointer-events: none`）。粒子は 150 を上限にする。
- 端末負荷が高い場合（フレーム落ち 3 回以上）は、粒数を半減して再描画する。

### 5.4 やりすぎ防止ルール
1. **同時演出は1つ**。重なったらキューに入れ、優先度は レベルアップ > 売れた > 発送 > 出品 > その他の順にする。
2. 大演出（L以上）は **操作をブロックしない**。タップすれば即スキップできる。
3. 同種の large 演出は **10 秒間に 1 回まで**。連続登録では 2 回目以降を medium に落とす。
4. 1日あたり burst は 3 回まで。以降は large に落とす。
5. 質問回答のような頻度の高い操作は **必ず S 規模以下**にする。
6. 画面全体の揺れ（shake）、点滅（3Hz 超）は使わない（光過敏への配慮）。
7. 設定で「演出: 派手 / ふつう / 控えめ / オフ」を選べる。初期値は「ふつう」。

### 5.5 reduced-motion 対応
`prefers-reduced-motion: reduce` のときの代替（アプリ内設定でも同じ状態にできる）:
- 紙吹雪、浮上、バウンド、フリップ、放射線は **すべて無効**。
- 代替として **静止した祝福バナー**（ゴールド縁、「ピコーン！」のテキストとアイコン）を 2 秒表示し、フェードのみ（160ms）で出入りする。
- カウントアップは廃止し、最終値を即時表示する。
- 画面遷移はクロスフェード 120ms に変更する。
- 音と触覚は独立した設定のまま変えない（モーションを減らしても、音を止めるとは限らない）。

## 6. サウンド仕様（Web Audio API で合成）

音源ファイルは不要。`OscillatorNode` + `GainNode`（+ 必要に応じて `BiquadFilterNode`）で作る。

### 6.1 共通ルール
- `AudioContext` は **最初のユーザー操作で `resume()`** する（モバイルの自動再生制限対応）。
- マスターゲイン既定は **0.5**。全 SE のピークは −12dBFS（gain 0.25）程度に揃える。
- エンベロープは `setValueAtTime(0.0001)` → `exponentialRampToValueAtTime(peak, t+attack)` → `exponentialRampToValueAtTime(0.0001, t+length)`。クリックノイズ防止のため、**アタック最短 5ms**、終端は 0.0001 まで落とす。
- 1 つの SE は **最大 4 ボイス**、全体の同時再生は 8 ボイスまで。

### 6.2 レシピ
音名は A4 = 440Hz 基準。

| SE名 | 構成 | 波形 | 周波数 | エンベロープ | 長さ |
|---|---|---|---|---|---|
| **tap**（回答） | 単音 | triangle | 660Hz | A 5ms / D 90ms、peak 0.12 | 0.10s |
| **check**（チェック） | 単音、ピッチ微上昇 | sine | 880→990Hz（linear 40ms） | A 5ms / D 120ms、peak 0.14 | 0.13s |
| **buckle**（カチッ） | ノイズ+低音 | 白ノイズ（BP 2.4kHz, Q 2）＋ square 180Hz | – | ノイズ A 1ms / D 40ms、低音 D 60ms、peak 0.18 | 0.07s |
| **pikon**（登録） | 2音上昇 | sine＋triangle 2倍音（0.3倍量） | 988Hz（B5）→ 1319Hz（E6）、間隔 90ms | 各 A 8ms / D 280ms、2音目は余韻 450ms、peak 0.22 | 0.55s |
| **pikon-pikon-n**（売れた） | 3音上昇＋和音 | triangle＋sine | 784→988→1319Hz（G5→B5→E6、間隔 80ms）→ 最後に 1319+1661+1976Hz（E6+G#6+B6）の和音 | 各 A 8ms / D 250ms、和音は D 700ms、peak 0.24 | 1.2s |
| **coin**（売上加算） | 2音 | square（LPF 5kHz） | 1319→1976Hz、間隔 50ms | A 3ms / D 150ms、peak 0.10 | 0.25s |
| **ship**（発送完了） | buckle → 上昇音 | buckle レシピ＋ sine 1047→1568Hz | – | 上昇音 A 8ms / D 400ms、peak 0.20 | 0.6s |
| **levelup** | 5音アルペジオ | triangle＋sine 0.5倍量（1オクターブ下） | 523→659→784→1047→1319Hz（C5 E5 G5 C6 E6、間隔 70ms） | 各 D 220ms、最終音のみ 900ms、peak 0.24 | 1.5s |
| **streak** | 2音（火が灯る） | sine＋ノイズの薄いスウェル | 587→880Hz（D5→A5） | A 20ms / D 300ms、peak 0.16 | 0.4s |
| **combo(n)** | 単音、n に応じて半音上げ | triangle | 784Hz × 2^(n/12)（n=0〜7） | A 5ms / D 140ms、peak 0.15 | 0.18s |

「ピコーン！」の質感: 2音目に **ごく浅いビブラート**（5Hz、±6cent）を加えると、ゲームの効果音らしい温かみが出る。

### 6.3 設定・マナー配慮
- 設定項目: **サウンド ON/OFF**、音量スライダ（0〜100%、初期 50%）、「大きな音を抑える」（マスター −6dB）。
- 初回起動時は **サウンド OFF から始め、最初の祝福の直前に**「音も鳴らす？」と軽く聞く（突然鳴る不意打ちを避ける）。
- **マナーモード配慮**: Web からデバイスのマナースイッチは取得できない。そのため、
  - 音は常にユーザー操作の直後にだけ鳴らす（バックグラウンドや通知では鳴らさない）。
  - `document.visibilityState !== "visible"` のときは鳴らさない。
  - 時間帯設定を用意する（既定: 22:00〜7:00 は自動でミュート）。
  - 「静かな場所」クイックトグルをホームのヘッダに置く（1 タップで音と触覚を一時停止）。
- イヤホン接続は検知できないが、初回の音量確認として「テスト再生」ボタンを設定に置く。
- `AudioContext` が使えない環境では、無音で動作し、視覚演出のみを行う。

## 7. ハプティクス

`navigator.vibrate(pattern)`。数値はミリ秒で、配列は 振動, 休止, 振動… の順。

| イベント | パターン | 意図 |
|---|---|---|
| 回答/チェック | `[10]` | 軽い手応え |
| コピー成功 | `[12, 40, 12]` | 二度押しの確認感 |
| バックル（カチッ） | `[8, 30, 20]` | 閉まる感覚 |
| 出品完了（ピコーン） | `[20, 60, 40]` | 2段の上昇 |
| 発送完了 | `[15, 40, 15, 40, 60]` | 三拍子 |
| 売れた | `[30, 50, 30, 50, 90]` | 最も強い祝福 |
| レベルアップ | `[20, 40, 20, 40, 20, 40, 120]` | 駆け上がる感じ |
| ストリーク更新 | `[25, 80, 25]` | 灯がともる |
| コンボ | `[10, 30, 10]`（n 連目は 10 を n に応じ最大 24 まで増加） | 勢いの蓄積 |

- 1 パターンの合計は **300ms 以内**を目安にする。
- **iOS Safari は `navigator.vibrate` 非対応**（PWA でも同様）。`"vibrate" in navigator` で機能検出し、非対応のときは触覚を静かに省略する。エラー表示や「非対応です」という警告は出さない。
- 非対応端末では、**視覚と音に少しだけ比重を寄せる**。例えば iOS では、ボタンの押下フィードバック（scale 0.97, 80ms）をわずかに強める。
- 設定: ハプティクス ON/OFF、強度（弱/標準/強。強度は振動時間の倍率 0.6 / 1.0 / 1.4）。
- `prefers-reduced-motion` とは独立に扱うが、「静かな場所」トグルでは音と同時に停止する。

## 8. ゲームバランス

### 8.1 XP 表
| 行動 | XP | 備考 |
|---|---|---|
| 写真を1枚トリミング完了 | +3 | 1品あたり最大 6枚 = 18XP |
| 質問に1つ回答 | +5 | 5問 = 25XP |
| 出品文が完成（全項目回答） | +20 | スキップありでも +10 |
| 価格を決定 | +10 | |
| 出品登録（「出品できた！」） | **+50** | ピコーン |
| 売れた | **+80** | 売上金に反映 |
| 発送チェック項目 | +5 / 項目 | |
| 発送完了 | **+60** | |
| 売れ残りの再出品/値下げ | +30 | 前向きな行動を評価 |
| 初めての◯◯（初回ボーナス） | +100 | バッジ連動 |

1品が出品〜発送完了まで通ると、およそ **300〜350 XP**。

### 8.2 レベル曲線
- 次レベルまでの必要XP: `need(L) = 80 + 40 × L`（L = 現在のレベル）
- 累計XP: `total(L) = 20L² + 60L − 80`（Lv.1 = 0XP, Lv.2 = 120XP, Lv.3 = 280XP, Lv.5 = 720XP, Lv.10 = 2,520XP）
- XPからレベル: `L = floor((−60 + √(3600 + 80 × (XP + 80))) / 40)`
- 目安: 最初の出品物（4〜6品）で Lv.5 前後に到達する。Lv.10 以降は緩やかになり、長く使っても青天井にならない。
- 称号（Lv別、`--title`）: Lv.1「見習い」/ Lv.5「ベルト締め」/ Lv.10「馬具師」/ Lv.20「ハーネスマスター」/ Lv.30「名ライダー」

### 8.3 ストリーク規則
- 1 日に **何か 1 つ**（写真 1 枚でも、質問 1 問でも、発送チェック 1 項目でも）で継続とする。
- 日付の区切りは **ローカル時間の午前 4 時**（夜更かしを不利にしない）。
- **おやすみ券**: 7 日継続ごとに 1 枚付与（最大 3 枚保有）。1 日空いたとき、自動で消費して継続を守る。
- 途切れたときは **ゼロに戻さず、「ベスト記録」を残し、新しい連続を「1日目」から始める**。メッセージは前向きに（§9 参照）。
- XP ボーナス: 3 日 +10 / 7 日 +30 / 14 日 +60 / 30 日 +150 / 100 日 +500（節目の 1 回のみ）。
- プッシュ通知は初期状態では出さない。出す場合も「〜が切れそう」とは書かず、**1 日 1 回まで、ユーザーが時刻を選ぶ**。

### 8.4 コンボ規則
- 前回の登録から **20 分以内**に次の出品登録をすると、コンボが続く。
- 倍率（XP のみに掛かる）: 1 連目 x1.0 / 2 連目 x1.2 / 3 連目 x1.5 / 4 連目以降 x2.0（上限）。
- コンボボーナスは **出品登録 XP のみ**に適用する。連投のための粗い出品を避けるため、「出品文が完成した出品」だけを数える。
- コンボが切れても何も失わない。チップが静かに消えるだけ。1 日の最高コンボは記録として残す。

|---|---|---|
| 1 | **はじめの一歩** 🔰 | 初めて 1 品を登録 |

| 3 | **おしゃべり職人** 🗣 | 質問を全項目回答した出品を 5 品 |
| 4 | **ピコーン三連** ⚡ | コンボ 3 連を達成 |
| 5 | **火種** 🔥 | ストリーク 7 日 |

- バッジは「装備」として実績画面に並べる。獲得時は burst 演出、以後は小さな光沢のみ。

### 8.6 売上金に応じた報酬
売上金は「頑張りの記録」であり、金額で優劣をつけない。報酬は **見た目と演出のカスタマイズ**に限る。

| 累計売上 | 報酬 |
|---|---|
| ¥10,000 | テーマカラー「ミント」解禁 |
| ¥50,000 | サウンドパック「8bit」解禁 |
| ¥100,000 | 紙吹雪スタイル「ゴールドのみ」＋バッジ #9 |
| ¥300,000 | アプリアイコン（ダーク/ゴールド）解禁 |
| ¥500,000 | 称号「大商人」＋ホームの背景テクスチャ（革の縫い目） |
| ¥1,000,000 | 特別演出（レベルアップ演出の拡張版） |

- 金額が大きい品（Pixel 10 Pro Fold など）で一気に到達しても、報酬は **ゆっくり 1 つずつ通知**し、一度に出し過ぎない。

### 8.7 罪悪感を煽らない設計
1. **失う表現を使わない**。「切れた」「失敗」「0 に戻る」を避け、ベスト記録と再開を前面に出す。
2. 減点なし。XP は増える一方で、減らない。
3. 売れ残りは「棚」であり、「失敗」ではない。長期の滞留にも赤や警告アイコンを使わず、warning は穏やかなオレンジに留める。
4. 通知は初期オフ。ユーザーが選んだ時刻のみ。
5. ランキング・他人との比較は持たない（個人用のため）。
6. 休む選択を応援する。「今日はおやすみ」ボタンを用意し、押してもストリークを消費しない（週 1 回）。
7. 「依存を促す演出」を避けるため、1 日の burst 回数に上限を設ける（§5.4）。

## 10. アクセシビリティ & 実装メモ

### 10.1 アクセシビリティ
- **コントラスト**: §2 の AA 基準を維持する。ダークモードも同じ基準で確認する。
- **フォーカス**: 全ての操作要素に `:focus-visible` のリング（2px primary + 2px オフセット）。
- **タップ領域**: 48×48px 以上、隣接要素との間隔 8px 以上。
- **ARIA**:
  - 祝福演出のテキスト（「ピコーン！ +50 XP」）は `role="status"` / `aria-live="polite"` で読み上げる。
  - XP バー・進捗は `role="progressbar"` + `aria-valuenow/min/max`。
  - 質問カードの選択肢は `role="radiogroup"` とし、矢印キーで移動できるようにする。
  - 紙吹雪の Canvas は `aria-hidden="true"`。
- **モーション**: `prefers-reduced-motion` と、アプリ内の「演出: オフ」の両方を尊重する（§5.5）。
- **音**: 音だけで情報を伝えない。全ての SE に視覚的なテキストまたはアイコンが対応する。
- **文字拡大**: OS のフォント拡大（最大 200%）で崩れないよう、`rem` 基準にし、固定高さを避ける。
- **色覚多様性**: 状態は色＋アイコン＋ラベルで区別する（success と warning を色のみで区別しない）。
- **ダークモード**: `prefers-color-scheme` に従い、手動切替も用意する（`data-theme` 属性）。
- **言語**: `<html lang="ja">`。数値は `Intl.NumberFormat("ja-JP")` で整形する。

### 10.2 デザイントークン命名
`--{カテゴリ}-{役割}-{状態}` の形で統一する。

```
色:       --c-base / --c-surface / --c-primary / --c-primary-press
          --c-xp / --c-xp-ink / --c-success / --c-warning / --c-danger
文字:     --fs-display / --fs-h1 … --fs-caption   --font-display / --font-body / --font-num
間隔:     --sp-1(4) --sp-2(8) --sp-3(12) --sp-4(16) --sp-5(24) --sp-6(32)
角丸:     --r-s(8) --r-m(14) --r-l(20) --r-pill(999)
影:       --sh-1: 0 1px 2px rgb(27 29 42 / 8%)
          --sh-2: 0 6px 18px rgb(27 29 42 / 12%)
モーション: --dur-fast / --dur-base / --ease-out / --ease-spring
```

### 10.5 実装メモ
- **演出の入口は 1 つ**: `celebrate("listed" | "sold" | "shipped" | "levelup" | "streak" | "combo")` を呼ぶと、視覚・音・触覚が設定に応じてまとめて実行される。画面側は演出の細部を知らない。
- `CelebrationHost` が優先度キュー（§5.4）と頻度制限を担当する。
- **オフライン**: PWA の Service Worker で静的アセットをキャッシュし、データは IndexedDB（出品・在庫・XP）に保存する。Workers 側は配信とバックアップ用の薄い API に留める。
- **画像**: 端末内で Canvas 処理（トリミング・補正）し、元画像と処理済み画像を両方保持する。サーバーへの送信はユーザーが明示的に選んだときのみ。
- **パフォーマンス目標**: 初回表示 LCP 2.5s 以内（4G 想定）、演出中も 50fps 以上。紙吹雪は `requestAnimationFrame` で描画し、画面が非表示になったら停止する。
- **OSS 配慮**: SE のレシピ・トークン・文言を設定ファイル（JSON/TS 定数）に切り出し、フォークで差し替えやすくする。フォントとアイコンは OFL/MIT のものだけを同梱する。
- **非公式の明示**: 設定画面の「このアプリについて」に「メルカリ公式ではありません。メルカリとは連携していません」と明記する。
